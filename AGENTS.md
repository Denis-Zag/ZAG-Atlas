6. Указывать, к чему относятся лимиты: вопрос, документ, контекст, название и файл; численные примеры помечать как значения по умолчанию и сверять с реализацией.

Основная серверная инструкция — запуск install.sh и ввод домена/ключа/пароля; подробности находятся в deploy/README.md. До фактической проверки не выдавать установщик за выполненный серверный деплой. Не добавлять обещания или упоминания срока серверной установки.
9. Установщик использует только compose.server.yaml, .env.server и отдельный проект zag-atlas-server. Не менять ради него локальные compose.yaml, .env, код приложения и существующие тома. Серверные секреты и файл домена не публиковать.
10. По согласованной доработке 18 ноября admin восстанавливается через python -m app.recover_admin владельцем установки. Это команда терминала, без HTTP-маршрута и без передачи пароля аргументом или переменной окружения. Сохранять обязательную смену, отзыв сессий admin и атомарный аудит без секретов. Рабочий пароль при проверках не менять; использовать временную базу. В документации — остановка atlas, одноразовый контейнер восстановления и последующий запуск atlas.

В README не восстанавливать раздел «Мини-экономика» и абзац о getpass/ATLAS_LOGIN_USER/ATLAS_LOGIN_PASSWORD. Описание показа пароля, длины 8–128 и ошибки повтора хранить в начале раздела «Вход, выход и сотрудники», сразу после заголовка (уточнение Дениса 18 ноября).
