# Восстановление пароля admin — 18 ноября 2026 года

Я добавил команду `python -m app.recover_admin` для владельца установки. В README приведены команды отдельно для локального Docker и серверного профиля. Приложение на время восстановления останавливается.

Проверки прошли на временных базах SQLite: 15 целевых тестов за 1,425 с; полный офлайн-прогон — 98 тестов за 36,912 с, без ошибок.

## Проверенное поведение

- Новый пароль хранится в виде хеша; старый пароль перестаёт приниматься. Все сессии admin отзываются, обязательная смена временного пароля включается. Вход и принудительная смена проверены через TestClient приложения.
- Документы, фрагменты, история вопросов, сотрудники и их сессии сохраняются. Очищается только счётчик неудачных входов для логина admin; ограничение по IP сохраняется.
- Успешное действие записывается как `CLI admin_password_recovery`. В аудите отсутствуют пароль, его хеш и соль. Ошибка записи аудита откатывает всю операцию.
- Отсутствующая база не создаётся автоматически. При неправильной схеме или отсутствии единственного admin восстановление не выполняется.
- Два скрытых ввода должны совпадать; длина — 8–128 символов. Отмена, неподдерживаемые параметры и невозможность скрытого ввода не меняют пароль. Аргумент с паролем или перенаправление stdin не поддерживаются.

## Границы проверки

Рабочий пароль admin не менялся, рабочая база не использовалась для восстановления. Контрольные суммы 18 существующих файлов локального приложения и конфигурации совпадают с исходным снимком; добавлен отдельный модуль команды, без изменения схемы и зависимостей. Платных запросов не было.

Docker Engine из сессии агента недоступен. Реальная интерактивная процедура внутри Docker и восстановление на настоящем VPS ещё не выполнялись. В тестах скрытый ввод моделируется подменой getpass; проверка логики не заменяет проверку конкретного терминала. Перед использованием команды требуется собрать актуальный образ по README. Пробный сброс действующего рабочего пароля для этой проверки не нужен.
