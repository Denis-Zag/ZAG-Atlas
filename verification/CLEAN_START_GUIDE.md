# Проверка воспроизводимого запуска ZAG Atlas

Выполнено 17 ноября 2026 года: passed, функциональная готовность за 142,498 с. [Фактический результат](CLEAN_START_RESULT_20261117.md). Инструкция ниже позволяет воспроизвести проверку; повторный прогон выполняет платные запросы.

## Запуск из Windows PowerShell

Предварительно нужны установленный и запущенный Docker Desktop с Linux Engine, Compose, интернет и действующий ключ ProxyAPI в рабочем .env. Python и OCR на Windows для этой проверки устанавливать не нужно: проверочный Python и Tesseract выполняются в новом контейнере.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\VibeProjects\Educational_projects\ZAG Atlas\scripts\verify_clean_start.ps1"
```

Команда работает из любой папки. На время проверки не добавляйте документы и вопросы в рабочий Atlas: скрипт сравнивает количество записей до и после. VPN отключать не требуется. Если порт 18080 занят, можно выбрать другой через параметр -Port; рабочий порт 8000 запрещён.

## Что проверяю

1. Создаю новую папку исходников в исключённом из публикации _rollback. Рабочие SQLite, настройки и векторный кеш в неё не копируются. В отдельный .env переношу только действующую строку ключа; остальные параметры беру из .env.example, первоначальный пароль генерирую случайно. Пароли и ключ не печатаются.
2. Использую уникальное имя Compose atlas-clean-ДАТА-ВРЕМЯ-СЛУЧАЙНЫЙ_СУФФИКС, отдельный локальный порт и два новых именованных тома. Проверяю итоговую конфигурацию, чтобы не было подключения рабочих данных.
3. Выполняю compose pull qdrant и compose build --no-cache --pull atlas, затем запускаю весь отдельный Compose с ожиданием готовности.
4. Проверяю HTML/статику, пустые documents/snippets/qa_runs/embedding_cache, единственного первоначального администратора, пустой Qdrant и наличие Tesseract rus+eng/Poppler.
5. Проверяю вход и обязательную смену пароля, профиль компании, добавление инструкции и индексацию, подтверждённый ответ с дословной цитатой, недостаток знаний без технической ошибки, историю, аудит, JSON/CSV и выход. Это максимум два вызова языковой модели плюс эмбеддинги; намеренного повторного прогона платных вопросов нет.
6. Сохраняю JSON и краткий текст в verification/CLEAN_START_ДАТА-ВРЕМЯ-СУФФИКС.json/.txt. Затем удаляю только временные контейнеры, тома и тег тестового образа, проверяю состояние контейнеров и количество записей рабочей установки.

## Как трактую время

Таймер начинается перед копированием исходников и подготовкой параметров. Отдельно фиксирую готовность инфраструктуры и завершение функциональной проверки. Статус passed требует успешных проверок, времени функциональной готовности не более 600 секунд, успешной уборки и неизменности рабочей установки. Превышение времени не скрывается.

Это имитация чистой установки на существующем Docker-хосте, которую допускает урок. Слои сборки приложения не используются повторно, но базовые образы Python/Qdrant могут уже находиться на компьютере; установка Docker/WSL и время ручного заполнения параметров в замер не входят. Нельзя выдавать такой результат за полный холодный запуск на новом компьютере.

В приватной папке проверки сохраняются временный .env и подробные журналы. Их не следует публиковать. Кеш сборки Docker глобально не очищается. Рабочие контейнеры не останавливаются.
